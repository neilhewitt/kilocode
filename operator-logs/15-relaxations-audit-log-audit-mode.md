## Decisions

- 2026-10-13 Audit mode ships on the unsandboxed dry-run path, engine path wired but gated. KNOWN RISK confirmed first, live and probe-gated in an isolated child on this base-container host: MXC SDK 1.0.0 `captureDenials` allow-mode kills the SDK host process with 0xC0000005; the byte-identical request without the `captureDenials` config enforces cleanly ("Access is denied.", no host artefact, exit 0). Audit mode therefore runs commands unsandboxed, composing the would-be grant table per command (translate dry-run) and logging it to the session audit JSONL under `RUNNING UNSANDBOXED (audit mode)`; `KILO_MXC_AUDIT_ENGINE=1` opts a host with a fixed engine into the real allow-capture path. `test/audit.test.ts` pins the crash today (asserts 0xC0000005 without the switch) and fails loudly when upstream fixes or regresses it.
- 2026-10-13 Relaxation model per ADR 0002: durable (config) relaxations are re-composed from config for every command and never persisted, so removing one restores the default table next session; ephemeral (prompt) relaxations live in the session snapshot and never seed the next session. Both are recorded in the session audit JSONL with their source — config entries once per session at init/enable, prompt entries at grant time via `sandbox.relax`.
- 2026-10-13 The relaxation seam is generic for ticket 17: kinds `path` (read/write) and `terminal` (recorded, composes nothing into a filesystem table); `SandboxRelaxation.grantable`/`appended`/`record` + `SandboxPolicy.relax` + HTTP `sandbox/relax` form the request/grant/record surface the PTY relaxation plugs into. `RunAudit` deliberately rejects a `mode` field — allow-capture is the only audit posture on the wire.
- 2026-10-13 Fail-closed everywhere: malformed relaxation entries never reach a table (`isRelaxation` gate shared by config resolve, store validation, and merge), a malformed or failed engine capture never masquerades as an audit summary (warnings carry failures), store snapshots with malformed `relaxations`/`audit` are rejected on read.
- 2026-10-13 Merge with ticket 16 (loopback proxy/egress): unions in sidecar `sdk.ts` (audit containment mapping + Model 1/2/3 egress composition, `RunBindings` threaded through `runThrough`), `sdk.test.ts` (my audit suites + their network suites, my helper renamed `auditCommand` for the shared `command` name), opencode `config.ts` (RelaxationEntry + audit schema + allowed_cidrs/resolveEgressPosture), `store.ts`/`policy.ts` (snapshot fields, limits/matches, `profile()` signature takes relaxations AND allowedCidrs positionally, execute passes both, gate-audit denial record carries both).
- 2026-10-13 Child sessions do not inherit prompt relaxations (each session grants its own; durable config ones apply to every session by recomposition); recorded as a scoping note for ticket 17's PTY work.

## Caveats

- Upstream blocker: MXC SDK 1.0.0 `captureDenials` allow-mode crashes the SDK host process (0xC0000005), reproduced in an isolated child; the engine path is wired end-to-end (RunCommand.audit → containment.config.captureDenials → RunResult.audit) but disabled by default. The canary test inverts when the switch is set (`KILO_MXC_AUDIT_ENGINE=1`): with the switch it requires a clean run with a capture report; without it it pins the crash. When upstream fixes it, flip the default and delete the pinning assertion.
- The would-be table in audit records is composed from a dry-run `translate` with the process environment; it records grants/denies/egress (full egress posture incl. cidr rules post-merge) but does not attempt to predict every individual denial the engine would capture (the engine path reports `totalDenials` + report path when enabled).
- Prompt relaxations are session-scoped and not inherited by child sessions (durable config relaxations are); ticket 17 may revisit family propagation for PTY grants.
- Audit-mode runs are unsandboxed by definition — the session status carries `audit: true`, the TUI shows `△ AUDIT — UNSANDBOXED`, and every audit record opens with the unsandboxed signal string.
- Host environment note: opencode bun:test files (including my `relaxation.test.ts` additions to policy/tui tests) run under CI's bun; this host verified them by syntax-check only, same approach as ticket 14/16.
